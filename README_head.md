# Inference-Pareto-Router### *Sub-millisecond 2D model-tier and reasoning-effort routing for LLM inference*[![PyPI version](https://img.shields.io/pypi/v/pareto-router.svg)](https://pypi.org/project/pareto-router/)[![Python versions](https://img.shields.io/pypi/pyversions/pareto-router.svg)](https://pypi.org/project/pareto-router/)[![License](https://img.shields.io/pypi/l/pareto-router.svg)](LICENSE)[![CI](https://github.com/Sandeep-Hipparagi/Inference-Pareto-Router/actions/workflows/ci-publish.yml/badge.svg)](https://github.com/Sandeep-Hipparagi/Inference-Pareto-Router/actions/workflows/ci-publish.yml)[![mypy](https://img.shields.io/badge/mypy-strict-success.svg)](https://mypy.readthedocs.io/)[![Routing latency](https://img.shields.io/badge/decision%20latency-p99%200.181%20ms-blue.svg)](#benchmarks)**Developed by [Sandeep Hipparagi](https://www.bluepatterns.ai/).**Every prompt that reaches an LLM costs two independent resources: the *tier* of themodel you send it to, and the *test-time reasoning effort* you let that model spend.Almost every router in the wild optimises one dimension — cheap model versusexpensive model — and then throws a fixed reasoning budget on top. That is why agreeting can burn 8,000 thinking tokens on a frontier model while a proof requestgets a one-shot answer from a mini model.Inference-Pareto-Router treats routing as a **point in a 2D space**. It scores aprompt on two orthogonal axes, `logic` (verifiability, algorithmic depth, math/codestructure) and `knowledge` (entity richness, domain nuance, world knowledge), andreturns a coordinate `(ModelTier, ReasoningEffort)` together with the exact,provider-ready request body that implements it — in roughly **0.1 ms at the median**,with no network call in the decision path. The in-repo 100-scenario benchmarkreports mean 0.099 ms and p99 0.181 ms; the first call in a process pays a one-offwarmup of a few milliseconds.---
